# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**AIMS** (Asset/Infrastructure Management System) — branded **SIMS** (Structural Integrity Management System) in the UI — a .NET 10 Clean Architecture web app for Badak LNG (Bontang, Indonesia) to track structural/civil assets (tanks, foundations, pipelines, etc.) across plants, with condition inspection (Good/Fair/Poor), GIS mapping, and audit trail. Razor Pages + Dapper (no EF Core), Autofac-hosted DI (properly wired 2026-07-14 via `builder.Host.UseServiceProviderFactory` — the original wiring built a container and discarded it, so the app silently ran on MS DI), dual SQL Server/Oracle support.

`docs/PROJECT_STUDY.md`-style deep dive lives in `PROJECT_STUDY.md` at the repo root — read it for exhaustive entity/service/page tables. **It is dated 2026-06-29 and predates the Plant-entity refactor, the `LookupCodes.cs` lookup tables, and the `Condition`/legacy-field cleanup described below** — trust the current code over that file for `AssetItem`/`Plant` shape. `WORK-SUMMARY-*.md` files log day-by-day changes chronologically and are more current.

The `SIMS Dashboard Rev A/B *.pptx` files are the UI design spec (wireframes built as native PowerPoint shapes, not screenshots) that pages under `Pages/AssetItems`, `Pages/Plants`, and `Pages/Index.cshtml` are being built to match. When asked to study or implement against them, extract via `python3 -m zipfile` (no `unzip`/LibreOffice available in this environment) — slide XML text runs (`<a:t>`) give the copy, shape `<a:xfrm>`/`<a:solidFill>` give layout and color, embedded media are photos/charts, not screenshots of the actual UI.

## Commands

```bash
# Build
dotnet restore AIMS.sln
dotnet build AIMS.sln

# Run (DatabaseProvider defaults to Oracle per appsettings.json)
dotnet run --project src/AIMS.WebFrontend
# ...or force SQL Server:
DatabaseProvider=SqlServer dotnet run --project src/AIMS.WebFrontend   # bash
$env:DatabaseProvider = "SqlServer"; dotnet run --project src/AIMS.WebFrontend  # PowerShell
```

Tests live in `tests/AIMS.WebFrontend.Tests` (xUnit): `dotnet test tests/AIMS.WebFrontend.Tests/AIMS.WebFrontend.Tests.csproj`. Page-model tests run the real Dapper SQL against a shared in-memory SQLite database via the `SqliteDapperContext` test helper — no SQL Server/Oracle needed.

### Production deployment

Two scripts, run in order, share one gitignored `deploy/deploy.conf` (copy from `deploy/deploy.conf.example`):

- `deploy/upload.sh` runs on your **dev machine**. It zips the repo's tracked-ish source (excludes `.git`, `bin`/`obj`, `.vs`, logs, `deploy.conf` itself, and the runtime upload dirs `wwwroot/asset-pictures`/`asset-documents`) with `python3 -m zipfile`/`zipfile` module — not the `zip`/`unzip` CLIs, since neither is guaranteed installed locally or on the server, same reasoning as the `.pptx` extraction note below — then `scp`s it over and extracts it into `REMOTE_DIR` on the server.
- `deploy/deploy.sh` then runs **on the target Ubuntu server itself** (in an SSH session, from that extracted checkout), not from the dev machine: an earlier version tried to publish locally and `rsync`/`ssh` the result over, but password-based SSH in this environment can't satisfy `sudo`'s password prompt through a piped/non-tty connection (rsync's internal `ssh` has no real terminal, and even shipping the provisioning script over `ssh -t` left stdin occupied by the script itself), so running locally on the box sidesteps the whole problem. It deploys `AIMS.WebFrontend` behind nginx (plain HTTP reverse proxy) with Oracle installed locally on that same server, and is idempotent: first run installs the ASP.NET Core runtime, nginx, and a dedicated `aims` system user; every run publishes a new timestamped release directly into `/opt/aims/releases/`, symlinks persistent data (`appsettings.Production.json`, `wwwroot/asset-pictures`, `wwwroot/asset-documents`, `Logs/`) in from `/opt/aims/shared/` so uploads and secrets survive redeploys, flips the `/opt/aims/current` symlink, restarts the `aims-webfrontend` systemd service, reloads nginx, and prunes old releases. Oracle itself is not installed/configured by the script — it's assumed already running on the server at `localhost:1521`; only the connection string in the shared `appsettings.Production.json` needs the real password.

### Database backup/restore

`deploy/db_backup.sh` (`backup` / `restore <file> [--yes]` / `list` subcommands) runs on the same server, reusing `deploy/deploy.conf`. It reads the live Oracle connection string straight out of `$BASE_DIR/shared/appsettings.Production.json` and does a schema-level Data Pump export/import (`expdp`/`impdp`) of the app's DB user, writing timestamped `.dmp`/`.log` files to `$BASE_DIR/backups` (pruned to `KEEP_BACKUPS`, default 7). `restore` is destructive (`table_exists_action=replace`) and requires typing `yes` unless `--yes` is passed.

Creating the Data Pump `DIRECTORY` object needs a DBA connection, which the script gets via OS authentication (`sqlplus / as sysdba`) rather than a documented SYS/SYSTEM password — it auto-detects whether Oracle is the `setup_oracle_xe.sh` podman container (by container name) and runs everything through `podman exec --user oracle` + `podman cp`, or otherwise assumes a native install and runs as the host's `oracle` OS user via `sudo -u oracle -i` (a login shell, so its own oraenv/profile sets `ORACLE_HOME`/`ORACLE_SID`). The native-install path is unverified — only the podman-container path has been checked against `setup_oracle_xe.sh`'s actual setup. The DB password is deliberately kept out of any command line (visible via `ps` otherwise) — it only ever goes into a Data Pump parameter file written with tightened permissions and deleted immediately after use.

Because this deployment model has no TLS anywhere (nginx terminates plain HTTP only), `Program.cs` deliberately does **not** call `UseHttpsRedirection()`/`UseHsts()` outside Development — those would otherwise redirect-loop every request since Kestrel never sees an HTTPS scheme. Don't re-add them without also adding real TLS termination.

**Logging:** `Program.cs` uses Serilog (`Serilog.AspNetCore`) as the sole logging provider — console plus a rolling file sink — reading sinks/levels from the `Serilog` section of `appsettings*.json` (fixed 2026-07-14: an earlier version of this same change built `Log.Logger` entirely in code and called `builder.Host.UseSerilog()` with no arguments, which silently ignored that JSON section — `ReadFrom.Configuration` is required for it to actually take effect). The plain ASP.NET Core `Logging` section is gone from `appsettings.json`/`appsettings.Development.json` since it's dead once Serilog owns logging — overrides belong under `Serilog:MinimumLevel` instead. The file sink writes to `Logs/aims-.log`, resolved relative to the working directory (the project dir under `dotnet run`; in production, `deploy/deploy.sh` symlinks each release's `Logs/` to a persistent `shared/Logs/` dir — same pattern as `asset-pictures`/`asset-documents` — so history survives redeploys and release pruning). A bootstrap console-only logger covers the window before config loads, including `InitializeDatabase()`'s schema-init pass which runs before `builder.Build()`; `app.UseSerilogRequestLogging()` logs each HTTP request; a top-level `try/catch/finally` around `app.Run()` calls `Log.Fatal`/`Log.CloseAndFlush()` on startup failure so it isn't lost. Don't reach for `Console.WriteLine` for diagnostics — inject `ILogger<T>` instead (see `LoginModel`'s exception handler).

There's no headless browser (no chromium, Playwright is Windows-side Node with WSL path friction) — verify UI changes by rebuilding, running the app, and inspecting HTTP responses/markup, or ask the user to check in a real browser.

**Razor compiler gotcha (this .NET 10 SDK):** a code block whose markup starts on the same line as `{` (e.g. `{ <span>...</span> }`) or has blank lines immediately after `@if (...) {` before the first tag fails to parse — and the failure cascades into unrelated bogus errors elsewhere in the same compilation (unrelated files, "top-level statements" duplication, etc.), making the real cause hard to spot. Always put markup on its own line right after the opening brace. If a build suddenly produces a wall of nonsensical errors across many files, clean `obj`/`bin` for `AIMS.WebFrontend` and look for this pattern first before assuming something else broke.

## Architecture

Dependency direction: `AIMS.WebFrontend → AIMS.Infrastructure → AIMS.Core → AIMS.SharedKernel` (Core has zero infrastructure dependencies).

- **AIMS.SharedKernel** — `BaseEntity`, `ValueObject`, `IRepository`, `IHandle<T>`, `IDomainEventDispatcher`, `IAuditUserProvider`, `IActivityLogger`.
- **AIMS.Core** — domain entities (`Entities/AssetItem.cs` holds `AssetItem`, `Plant`, `AssetItemRemarks`, `AssetItemDocuments`, `DocumentTypeCode`; `AssetItem` has a `Category` field (`string?`, `nvarchar(250)`) added 2026-08-04, displayed as a select dropdown in Create/Edit pages with options "Equipment / Main Structure" and "Foundation / Supporting Structure" — moved to the **Asset Register** section (from Asset Attribute) on 2026-08-04, and shown read-only in the Asset Register table in Details; `Entities/LookupCodes.cs` holds static lookup tables `EquipmentCode`/`CivilAssetCode`/`PlantCode` used for dropdowns and tag generation — `PlantCode` (added 2026-07-23) maps a fixed Plant `Code` → `Description` reference list, used to render the `Code` field as a select and auto-fill `Description` on the Plants Create/Edit pages; Plants themselves remain a fully DB-backed entity managed via the `/Plants` CRUD pages, not seeded from this static list, since `DatabaseInitializer`/`OracleSchemaInitializer` dropped that seeding step on 2026-07-08), domain events/handlers, `AuditLog`. `AssetItemRemarks`/`AssetItemService.GetRemarksAsync`/`AddRemarkAsync` still exist but are unreachable from the UI since the Condition (GVI) tab's remarks section was removed 2026-07-07 in favor of the picture carousel.
- **AIMS.Infrastructure** — Dapper repositories, the SQL Server/Oracle strategy-pattern abstraction, Dapper-backed ASP.NET Core Identity stores, audit logging, startup extensions (`StartupSetup.cs`), Autofac modules (`DependencyInjection/CalculationsModule.cs`). DI is hybrid: plain `IServiceCollection` registrations in `StartupSetup.cs`/`Program.cs` get `Populate()`d into the Autofac root container (`builder.Host.UseServiceProviderFactory` in `Program.cs`); Autofac-specific wiring (assembly scans, decorators) lives in modules registered via `ConfigureContainer`. The old `ContainerSetup.cs` (which built a container and discarded it) was deleted 2026-07-14 when the hosting was wired properly. Per-EquipmentCode calculation strategies (`AIMS.Core/Services/Calculations/`): implement `IEquipmentCalculation` in that namespace and the assembly scan registers it automatically; `ConditionAdjustedCalculation` is layered over every strategy via `RegisterDecorator` (keep it excluded from the scan); `IEquipmentCalculationResolver` picks the strategy by `EquipmentCode` with `DefaultEquipmentCalculation` (empty code) as fallback. Interval values are placeholders pending real engineering numbers. `AssetItemService.DeleteAsync`/`PlantService.DeleteAsync` run their multi-statement deletes (documents/remarks/asset; detach-assets/plant) inside a DB transaction (fixed 2026-07-14 — previously a failure mid-sequence could leave child rows deleted but the parent row intact). `FileUploadHelper.DeleteFile` canonicalizes the target path and refuses to delete anything that resolves outside `wwwroot` (hardened the same day against a path-traversal `../` payload in a stored file path).
- **AIMS.WebFrontend** — Razor Pages UI. There are no EF migrations anywhere; the old empty `AIMS.Migrations.{SqlServer,Oracle,PostgreSQL}` placeholder projects were dropped from the solution and their now-orphaned `bin`/`obj` artifact dirs deleted 2026-07-14 — don't recreate them.

### No EF Core, no migrations — idempotent DDL instead

Schema is created/altered by `ISchemaInitializer` (`DatabaseInitializer.cs` for SQL Server, `OracleSchemaInitializer.cs` for Oracle), run on every app startup via `services.InitializeDatabase()`. All DDL is guarded (`IF OBJECT_ID(...) IS NULL` / Oracle `EXECUTE IMMEDIATE` with `ORA-00955` catch) so re-running is always safe. **Adding a field means adding a guarded `ALTER TABLE` block to both schema initializers**, not writing an EF migration.

One-time data backfills (e.g. seeding `Plants` from the old hardcoded lookup, migrating a legacy `IntegrityStatus` enum into the `Condition` string field, dropping now-unused legacy columns) are also written as idempotent C# migration steps inside these same initializer classes — see `MigrateLegacyIntegrityStatus` / `DropLegacyAssetItemColumns` for the pattern: backfill before drop, and run every boot behind existence checks.

### Oracle compatibility layer

Oracle uses `:Name` bind params while Dapper/SQL Server code is written with `@Name` — `OracleParamConnection`/`OracleParamCommand` rewrite parameters and coerce `DbType.Boolean` to `Int32` transparently. `ISqlDialect` (`SqlServerDialect`/`OracleDialect`) abstracts identifier quoting, insert-and-return-id, and pagination (`OFFSET/FETCH` vs `ROW_NUMBER()`) so `DapperRepository`/service classes stay provider-agnostic.

`OracleParamConnection.BeginDbTransaction` maps `IsolationLevel.Unspecified` (what a parameterless `conn.BeginTransaction()` passes) to `ReadCommitted`, since ODP.NET raises `ORA-50002` on `Unspecified` directly — fixed 2026-07-14 alongside the `AssetItemService`/`PlantService` transactional-delete fix above; before that, no transaction had ever actually been opened successfully through this wrapper. `ISqlDialect.EscapeLike` (added the same day) escapes user-supplied `LIKE` search terms so a literal `%`/`_` in the search box doesn't act as a wildcard — SQL Server's implementation also escapes `[` (its character-class opener), which Oracle's must not do since escaping a non-wildcard character there raises `ORA-01424`. Callers pair it with an explicit `ESCAPE '\'` clause and `UPPER()` on both sides for case-insensitive matching (Oracle's `LIKE` is case-sensitive by default, unlike SQL Server's) — see `AssetItemService.GetPagedAsync`'s search clause and the Audit Logs username filter.

### Asset tagging

`AssetItem.AssetId` (the human-facing tag) is **always computed server-side** via `AssetItem.GenerateAssetId(plantCode, equipmentCode, civilAssetCode, civilAssetOrder, category)`, called from `AssetItemService.CreateAsync`/`UpdateAsync`. It is never a bound/editable form field — the UI shows a read-only, JS-live-updated preview instead. Keep this generation logic out of any new form input binding.

**Category-based formula (2026-08-04):** The tag format depends on `AssetItem.Category`:
- `"Equipment / Main Structure"` → `{plantCode}{equipmentCode}` (e.g. `17D`)
- `"Foundation / Supporting Structure"` → `{plantCode}{civilAssetCode}-{civilAssetOrder}-Q` (e.g. `17D-1-Q`)
- `null`/other → legacy combined format `{plantCode}{equipmentCode}/{civilAssetCode}-{civilAssetOrder}` (e.g. `17D/4-2`)

The JS preview in `Create.cshtml`/`Edit.cshtml` mirrors this logic client-side, watching `#Input_Category` alongside the other tag fields. The schema initializers' `RegenerateAssetIds` migration also fetches `Category` and passes it through to recompute existing rows on startup.

`Plant.Code` is `int?` (migrated from `string?` on 2026-07-07 — see idempotent `MigratePlantCodeToInt` in both schema initializers for the string→int conversion of existing rows). `AssetItem` has no `QrCode` field — the QR image always encodes `AssetId`, generated on the fly by `Pages/AssetItems/QrCode.cshtml.cs` and surfaced via a "View QR Code" button that opens `PrintTag.cshtml` in a small popup (see `openCenteredPopup()` in `site.js`) rather than a stored URL.

- `Pages/Shared/_Layout.cshtml` defines a white, centered top bar (3-column CSS grid: hamburger left, `badak-lng-large.png` logo + "Structural Integrity Management System (SIMS)" title centered, nav/user menu right) plus a role-based sidebar (Asset Tree) and a generic drag-to-resize right panel (`.sims-panel-resizer`, 240–560px clamp) that any page can opt into via `@section RightPanel`. **Asset Register, Map Demo, and System(Admin)/Management/My Audit Trail live in the top bar, not the sidebar** (moved there 2026-07-07, styled as `.sims-topbar-nav-btn` pills per the mockup's slide 6) — don't go looking for them in the Asset Tree markup. The Admin-role dropdown was labeled "Administration" until 2026-07-10, when it was renamed to "System" and its "Role Management" link removed (the `/Admin/Roles/Index` page itself still exists, just unlinked from the menu).
- `Pages/Shared/_SiteMapScripts.cshtml` is the single shared Leaflet + QGIS-Server-WMS init (auto-discovers layers via `GetCapabilities`) reused by the Home dashboard and the Plant asset-tree map view — don't duplicate map init JS per page.
- Condition badges (`Good`/`Fair`/`Poor`) use a fixed color mapping (green/amber/red) consistent across the dashboard, asset list, and mockup spec — check `site.css` (`.condition-dot`, `.sims-progress-bar`, `--sims-condition-*` vars) and `Pages/Index.cshtml` (Chart.js `backgroundColor`) before introducing new status colors. Fair uses `#e6b800` (amber, switched from `#ffff00` on 2026-07-14) in both the CSS variables and the Plant Summary chart.
- Plant references in the UI display as `Code - Description` (or `Code` badge + `Description`), not `Code - Name` — standardized 2026-07-23 across the Plants Index list, sidebar Asset Tree titles, the `AssetItems` Create/Edit Plant select, and the Asset Register list/filter. Keep any new Plant-referencing UI consistent with that. **Exception (2026-07-24):** the sidebar Asset Tree's visible plant label (`_Layout.cshtml`, `.sims-tree-label`) intentionally shows `Plant.Name` instead, since the tree is meant to read as a short plant name list at a glance — the `Code - Description` form still appears in that same link's `title` tooltip.
- There is no lat/lng geo model yet — `AssetItem.CoordinateN`/`CoordinateE` are free-text, not a real coordinate system, so all map views currently render the same site-wide QGIS layer rather than a true per-plant/per-asset pin.
- On `AssetItems/Details.cshtml`, the Inspection, Risk Based Inspection, Technical Document, and Documentation tabs render a shared `_ModuleLocked.cshtml` partial ("Module Locked" + padlock, per mockup slide 21) instead of real content — this is a deliberate design-phase lock, not a missing feature. The Documentation tab's upload/list/delete backend in `Details.cshtml.cs` still works, it's just not reachable from the UI. The Condition (GVI) tab instead shows a picture-preview carousel (slide 16) sourced from pictures uploaded via `EditCondition.cshtml`, which stages files client-side (JS + `DataTransfer`, no per-file postback) and uploads them together with the condition update on Save (slide 17).
- `AssetItemDocuments.DocumentType` (`DocumentTypeCode.Picture` / `.Document`) distinguishes condition-tab picture uploads from general documents sharing the same table — filter on it (`DocumentType == DocumentTypeCode.Picture`) when displaying pictures rather than assuming every row is an image. `EditCondition.OnPostAsync` reloads that picture list on the `ModelState`-invalid path (fixed 2026-07-14) — only `OnGetAsync` populates it otherwise, so a validation error would render the carousel empty.
- Audit Trail timestamps are stored/queried in UTC but displayed in **each viewer's own browser timezone** (2026-07-14): `AuditLogs.cshtml.cs` emits ISO-8601-with-`Z` via `ToIsoUtc()` into a `data-utc` attribute, and a `@section Scripts` snippet reformats every `.js-local-time` element client-side (with a `… UTC` no-JS fallback). This replaced a server-TZ-dependent `.ToLocalTime()` that showed UTC on the UTC-configured deploy box — don't reintroduce `ToLocalTime()`. `AuditLogsModel.OnGetAsync` also adds the paging `@Offset` only *after* clamping `CurrentPage` to `[1, TotalPages]` (fixed same day) so a too-large `?page=` shows the last page's rows, not an empty result.
- `site.js` (now actually loaded from `_Layout.cshtml` — it wasn't for most of the project's history) provides `openCenteredPopup(url, name, width, height)`, used for the QR-code/PrintTag popups; reuse it for any future popup windows instead of a raw `window.open`.

### Roles

Three seeded roles — `Admin` (full access), `Manager` (user management + audit view), `User` (self-service) — enforced via Razor Pages `[Authorize(Roles=...)]`. The `Admin` role and the seeded `admin` account are protected from deletion/self-deletion in the Roles/Users pages. Beyond self-deletion, `Admin/Users/Index.cshtml.cs` and `Admin/Users/Roles.cshtml.cs` (hardened 2026-07-14) also refuse to delete/demote the seeded `admin` account specifically (by username) and refuse to remove the last remaining user holding the `Admin` role — either would otherwise lock everyone out of user/role management.
